# AWS F2: what the platform gives us

Facts for the architecture (M2), from public AWS and AMD documentation, read
2026-10-04. Each value is marked as quoted (from a source), computed (from
quoted values), or measured by AWS. "To verify" means no source states it.
Units: GB = 10⁹ bytes, GiB = 2³⁰ bytes.

## Memory on the FPGA card

| | value | kind | source |
|---|---|---|---|
| HBM capacity | 16 GiB, in the FPGA package | quoted | [1], [5] |
| HBM ports | 32 AXI3 ports, up to 450 MHz | quoted | [5] |
| HBM port width | 256-bit read, 256-bit write | quoted, to verify; consistent with [5] | [6] |
| HBM peak | 460.8 GB/s (32 × 32 B × 450 MHz); AWS and AMD give 460 GB/s (AMD: 32 pseudo channels × 14.375 GB/s) | computed; quoted | [5], [7] |
| HBM measured | read 426.28 GB/s, write 433.69 GB/s (all 32 ports), latency read 280 ns, write 172 ns | measured by AWS | [5] |
| HBM port reach | any port can reach any address, through a built-in switch | quoted, to verify | [7] |
| DDR4 | one 64 GiB DIMM, 72-bit (64 data + ECC), one 512-bit AXI4 port | quoted | [3], [5] |
| DDR4 controller | registered DIMM (RDIMM), part `M393A8G40BB4-CWE`, clock period 938 ps | quoted | [10] |
| DDR4 data rate | 2133 MT/s (2 transfers per 1066 MHz clock) | computed | [10] |
| DDR4 peak | 17.1 GB/s (2133 MT/s × 8 bytes), 27× less than HBM | computed | [10] |

The AWS blog says "460 GiB/s" for HBM [2]. The port arithmetic gives 460.8
GB/s, which is 429 GiB/s. We use GB. AWS's measurement does not say whether
its GB means 10⁹ bytes. If it does, the measured read rate is 92.5% of the
port peak.

## Shell interfaces

The shell is the fixed AWS logic around our design (the "custom logic", CL).

| interface | protocol | width | who starts transfers | use for us |
|---|---|---|---|---|
| OCL | AXI-Lite | 32-bit | host | control registers (BAR0, 64 MiB) |
| PCIS | AXI4 | 512-bit | host | host writes into card memory (BAR4, 128 GiB) |
| PCIM | AXI4 | 512-bit | our design | our design reads and writes host memory |
| DDR | AXI4 | 512-bit | our design | the DDR4 DIMM |
| HBM | AXI3 ×32 | 256-bit | our design | we instantiate the HBM IP ourselves |
| Interrupts | pulse handshake | 16 sources | our design | e.g. token done |

All quoted from [3]. The HBM monitor interfaces must be connected, or AWS
refuses to build the image [3]. HBM ECC scrubbing must stay off in the Small
Shell [9].

## Clocks

- `clk_main_a0`: 250 MHz. Every shell interface runs on it [3].
- Extra clocks come from the `AWS_CLK_GEN` IP in fixed recipes, for example
  450 MHz and 225 MHz (recipe B2), or 500 MHz (A1) [8].
- The HBM ports run up to 450 MHz [5].

Computed: at 250 MHz the 32 HBM ports carry at most 256 GB/s, 56% of the
450 MHz peak. Using the full HBM bandwidth needs a faster clock domain for the
memory side.
