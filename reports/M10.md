# M10 checkpoint: the core on F2 at 200 MHz

Core build 9 (floorplan of step 7, routed by a route-only run, core9r2) ran
SmolLM2-135M-Instruct on an f2.6xlarge with `clk_hbm_axi` set to 200 MHz at
run time (D-064). Decisions: D-074 (timing accepted as missed, gate -0.6),
D-075 (M10 closed at 200 MHz and 48% of the bound). The tables below are
copied from [data/f2/2026-11-14-core-run4.txt](data/f2/2026-11-14-core-run4.txt),
which model/reporting/m9.py generated from the run's logs.

## Timing: builds 4-9

The first full build (core 1) missed 250 MHz by 5.466 ns. After the vector
unit was pipelined (steps 1-6), the work was floorplanning the 3-SLR part.
Numbers from `data/f2/*core*.txt`:

| build | change | post-place WNS | post-phys_opt WNS | outcome |
|---|---|---|---|---|
| 4 | | -2.843 | | stopped at place |
| 5 | hard per-SLR pblocks | -1.268 | | stopped at place |
| 6 | register after each SLR crossing | -0.638 | -0.366 | stopped at phys_opt |
| 7 | HBM stages per SLR | -0.386 | -0.176 | route failed: congestion |
| 8 | group 7 to SLR2, SLR1 logic out of corridor | | | DRC (empty pblock), fixed |
| 9 | build 8 + fix | -0.596 | -0.317 | stopped by our -0.25 gate; its checkpoint routed later (core9r2): WNS -0.682, TNS -2798, 14,782 failing endpoints, all clk_hbm_axi, hold met |

Routability, not slack, was the blocker: build 7's router stalled at about
2,300 overlaps; build 9's floorplan routed to zero (route 7 h 32 min, peak
23 GB). The miss is at floorplan level (the worst paths are in the engine and
the host block), so closing it is a redistribution of SLR1's load, not
a tuning step. Cost of the route-only runs: about $9 (core9r, killed by its
deadline) and $13 (core9r2), estimates; see the data files.
