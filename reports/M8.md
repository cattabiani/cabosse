# M8 checkpoint: F2 bring-up (no model)

A bring-up design (`platforms/f2/bringup/`: 32 HBM test engines,
registers, the host's path to HBM port 0) was built in AWS's Small Shell
and run on an f2.6xlarge. Numbers come from the runs' result files,
summarized by `scripts/f2/bringup_report.py`:
[run 1](data/f2/2026-11-03-f2run1.txt), [run 2](data/f2/2026-11-03-f2run2.txt)
(raw: the `.jsonl` next to them), [build 4](data/f2/2026-11-03-bringup-build4.txt).

## Result

| criterion | measured | met |
|---|---|---|
| Register access works | OCL reads of SCRATCH, median 1.37 µs (run 1) and 1.36 µs (run 2), n 10,000 | yes |
| DMA works | host writes of 64 MiB through PCIS at two offsets, checked by the engine on port 0: 0 bad beats; host reads of 4 MiB: 0 bad words (run 2) | yes |
| HBM bandwidth per port and in total, measured | below; run 2 repeats run 1 within 0.5% | yes |
| Worst slack at 250 MHz ≥ 0 | build 4: WNS +0.069 ns, WHS +0.010 ns | yes |

The engine's own build in the shell moved to M9's first step (D-066).

## Measured

Core clock (`clk_hbm_axi`, D-065) set to 250, 200 and 125 MHz; measured
249.996, 199.997 and 124.998 MHz. Rates are each port's beats (32 bytes)
over its own cycle counter; a total is all beats over the slowest port's
time.

| at 250 MHz | result |
|---|---|
| All 32 ports read, or write, bursts of 2 to 16 | 256 GB/s in total, 8.0 GB/s a port: one beat per cycle, the port's limit |
| Each port reading alone | 8.0 GB/s, every port |
| All ports reading and writing at once | reads 194 GB/s beside writes 256 GB/s (200 MHz: 201 beside 205; 125 MHz: no loss) |
| One-beat bursts | reads 4.0, writes 6.0 GB/s a port (half and three quarters, at every clock: a limit in the core's clock domain) |
| Bursts in flight, one-beat reads | rate grows with the limit up to 32; up to 14 one-beat writes in flight, as many as the rate needed |
| All ports reading the other stack | 1.0-2.7 GB/s a port, 32 GB/s in total |
| All ports on one pseudo channel | 8.0 GB/s in total, one port's rate |
| One-beat partial write against a full one | same rate, same mean response (18.3 cycles) |
| One-beat read latency, ports 0 and 31 | median 43-44 cycles (172-176 ns), p99 73-79 |
| Host PCIS writes (AVX2 stores) | 106 MB/s at offset 0, 2.0 GB/s at 8 GiB (one sample each) |
| Host PCIS reads | 15-16 MB/s |

Every rate scales with the core clock, so up to 256 GB/s the HBM never
limited a port; it shows only in reads and writes together.

## Open

- The two host write rates differ by 19 times; the cause is not known.
  Measure with repeats before M9 relies on it (either loads SmolLM2's
  weights in seconds).
- Whether the host's write-combining buffer joins a line's two 32-byte
  halves is not measured (the data is right either way).
- A partial write's effect on memory was not read back.
- The one-beat burst limits sit in the core's clock domain; to look at
  only if M9 needs short bursts.

## Cost

Four bring-up builds on c6i.8xlarge (two stopped early) and two F2 runs
of about 4 minutes: about $10 in all, an estimate from instance hours,
against M8's $50 cap. Build 3's AFI was made only to check the flow.
