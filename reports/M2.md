are stale. Predictions are the perf model's, not measurements: no

## What was built

- `docs/f2.md`: the F2 platform facts (PR #12).
- `model/perf.py` and `docs/perf.md`: the first-order performance model,
  generic over model config, platform and design, with inputs validated and
  our measurements replacing documented values (PRs #13, #14, #15).
- An F2 check with AWS's public image (`scripts/f2/measure_sde.sh`, raw
  output in [data/f2/](data/f2/)): the PCIe link, host-card streaming and
  FPGA power (PR #17).
- `docs/architecture.md`: how a token runs, the blocks, the engine (128
  lanes × 4 multiply-adds), memory and clocks, the vector unit (16 elements
  per cycle), controller, commands and registers (PRs #18, #20, #21, #25).
- `model/commands.py`: the command list of one decode step and a reference
  controller that runs it on the golden functions, bit for bit against the
  golden decode step (PRs #20, #25).
- `A` = 16 and `S` = 128 in the numerics spec and the golden model (PRs #19,
  #21).

## Open issues

- **Nothing on F2 is measured by us yet.** HBM bandwidth, the 250 MHz clock
  and the command cost are documented values or guesses; the predictions
  are provisional until M8 (D-026).
- **The 4-cycle accumulate loop at 250 MHz** is a requirement on CVFPU's
  multiply-add (D-027). If it needs more cycles, `A` grows and the numerics
  change. First check in M3.
- **CVFPU's bit exactness is untested** (D-033). One mismatch is known
  already: RISC-V's `fmax` returns the other operand when one is NaN, the
  spec returns NaN.
- **Command overhead.** Primitive commands (D-031) give 44 commands per
  layer. At the guessed 64 cycles each they cost about a third of the
  memory time at position 0 if nothing overlaps (`docs/perf.md`); the
  controller must overlap command issue with streaming (M7).
- **The vector unit at long positions.** With M9's faster engine and memory
  it limits the token at long positions; fused softmax (D-031) or a wider
  unit (D-030) are the options.
- **Qwen2.5-0.5B's q, k and v biases** are not modelled (it is read as a
  Llama config). They are three ADD commands per layer, needed before M10.
- **Weight layout.** The engine reads weights in lane order (D-028); the
  command list and its HBM model use the checkpoint's logical shapes. The
  reordering is defined in M5.
- **Two AMD values in `docs/f2.md`** are still marked to verify.
