# M11: running SmolLM2-135M on F2, compared with other devices

Plain summary for readers outside chip design. Every number comes from a
saved log (paths below); estimates are marked.

## What was built

Cabosse is an open-source accelerator for running a language model one
token at a time. Here it runs SmolLM2-135M-Instruct (a small chatbot model)
on an AWS F2 instance, an FPGA (a chip that can be reprogrammed) next to a
host CPU. Anyone can launch it with `scripts/f2/launch_chat.sh`
(docs/f2-chat.md). The design runs at 200 MHz, below the 250 MHz it was
built for (it missed timing, D-074/D-075). Its output matches the Python
reference bit for bit.

## Why "share of the bound"

Producing one token reads every weight once, so a device cannot go faster
than its memory bandwidth divided by the model's size (the bound). A
device's tokens/s alone says little across such different hardware; the
share of its own bound shows how well it uses what it has.
Model size read per token: 270.9 MB (the BF16 file, estimate). Peak
bandwidths are datasheet values, not measured.

llama.cpp columns are at positions 0 / 46 / 1023 of the context. The F2
row is the 1000-token run's median over positions 45–1044. Cabosse's own
core, without the host, makes 316.8 tokens/s (48% of the bound); the
wall clock adds the logits read and host work (3.86 ms a token, of which
the core is 3.16).

Sources: reports/data/f2/2026-11-14-core-run5.txt (F2 and the F2 host's
CPU), reports/data/local/2026-11-14-llama/ (this PC; `summary.txt` has the
shares). The F2 peak is the rate of Cabosse's 32 HBM ports, one 32-byte
beat a cycle each (M8 measured each port reach it). Cabosse's bound counts
every byte its design reads, including the KV cache, which grows with
position (747.6 tokens/s at positions 0–127, 607.2 at 917–1044); the
llama.cpp rows count only the weight file, so their shares at position
1023 are somewhat low. With the weight file only, Cabosse's bound would
be 756 tokens/s and its share 34%. The F2 host CPU's bandwidth is unknown
(a shared cloud slice), so no share is given. The A10G and H100 peaks are
from memory of the datasheets, to verify.

## What the numbers mean

- End to end on this small model, the FPGA at 200 MHz (below its 250 MHz
  design clock) is level with the F2 host's CPU at short context (259.2
  against 283.0 / 260.4) and 29% faster at position 1023 (201.2). The
  core alone, without the host's share of each step, is 24–45% faster
  than that CPU (run 5's table). It is faster than this PC's CPU
  (241.0 at position 46, 186.7 at 1023).
- The GPU is not slower because it is a weak device: SmolLM2 is too small
  for it. Each token costs fixed launch overhead that bandwidth does not
  explain, so it reaches 38% of a bound that is six times higher. A
  larger model (M12) is the fair test; this report does not claim more.
- The CPU reaches 79% of its bound at short context, the best share here.
  Cabosse's 39% (48% for the core alone) is the room left to improve.
- The CPU baseline moves between instances (F2 host 224 on run 4, 283 on
  run 5); this PC varied 3–9% between its two runs (Nov 5 and Nov 14).

## Cost

F2 (f2.6xlarge): $2.475 an hour; a full run is about 15 minutes, about
$0.60 (estimate). This PC's hardware cost is not part of this report.
