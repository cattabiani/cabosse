## The vector unit

`rtl/vec_unit.sv`: 16 slots, each an `fp32_chain` (D-048: 7 FP stages that
every operation flows through, 50 cycles), over buffers of 16 banks with one
read and one write of 16 elements a cycle; a BF16 buffer converts up on
read and rounds on write.

- **Commands:** `ADD`, `MUL`, `FMA`, `EXP`, `RECIP`, `RSQRT`, `ROTATE_HALF`,
  the reductions `SUM`, `SUMSQ`, `MAX`, and `LOAD`, `KV_STORE`, `V_STORE`.
  A walker generates each command's addresses (rows of `m`, rows of `t` at
  the STRIDE register, D-049).
- **Reductions (D-050):** each slot keeps 8 partials, accumulated with its
  chain's first FMA; `rtl/vec_tree.sv` sums them in the spec's order on one
  adder.
- **Memory:** an AXI master of its own. `LOAD` reads the embedding row, RoPE
  rows and norm weights; `KV_STORE` and `V_STORE` write the cache in the
  lanes' order (D-062) through `rtl/port_wdma.sv`, done after the last
  write response (D-044).
- **Order:** the unit takes the next command while the previous drains
  (D-045); dones come in command order.

<!-- begin: share-why -->
At position 0 most of SmolLM2's vector time is latency, not work: `SUM` and `MAX` over 9 rows of one element each wait for the tree (168 cycles a row, Q-32), 90,900 of the unit's 219,597 cycles; and 785 commands wait for the one before (87 cycles each, Q-30).
<!-- end: share-why -->

At long positions softmax's five passes over the scores dominate (Q-29,
Q-31). Each fix would keep the bits; none is made yet (D-058).

## The engine's timing loop

and missed 250 MHz, so it was fixed in rounds (D-060, D-063), each named by
the build before it. Builds 0 to 3 ran out of context with Vivado's
default or explore directives; build 4 inside the Small Shell's CL region
with the shell's directives.

## Tests

- `verif/tests/test_fp32_chain.py` (driver `verif/bulk/fp32_chain.cpp`):
  every operation of one slot's chain, specials, each function's edges,
  random bits; slow: 10^8 random inputs per operation and the M1 exhaustive
  ranges.
- `verif/tests/test_vec_unit.py`: every command alone in every walk shape,
  softmax at the stride, reductions around the partials, random sequences
  of dependent and back-to-back commands, back-to-back speed.
- `verif/tests/test_vec_mem.py`: `LOAD` in every row mode and format,
  `KV_STORE` and `V_STORE` in every channel, random sequences with pausing,
  slow and erroring memories; the memory model's write side checks itself.

  slow: SmolLM2's at four positions.

  `overlap_ok`; `test_perf.py`: `vector_cycles`.
